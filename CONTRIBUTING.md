# Contributing

Thanks for helping improve the Azure Services Cheat Sheet.

## Contribution Style

- Keep it practical and concise.
- Prefer field-tested guidance over generic service descriptions.
- Use tables where they make decisions easier.
- Include security and cost notes when they affect the choice.
- Link to official Microsoft documentation when a link is useful.
- Avoid vendor-neutral filler and marketing language.

## Good Contributions

- Real-world gotchas.
- Service selection guidance.
- Small Azure CLI, Bicep, PowerShell, or .NET snippets.
- Architecture patterns with clear trade-offs.
- Corrections when Azure behavior or product names change.

## Markdown Guidelines

- Use one `#` heading per page.
- Keep heading levels ordered.
- Prefer short sections and scan-friendly tables.
- Keep Mermaid diagrams simple enough to render in GitHub.
- Use relative links for files in this repository.

## Pull Request Checklist

- Markdown renders cleanly.
- Internal links work.
- Mermaid diagrams render.
- Examples avoid hard-coded real secrets or tenant-specific IDs.
- New guidance is practical for developers, architects, or integration specialists.
